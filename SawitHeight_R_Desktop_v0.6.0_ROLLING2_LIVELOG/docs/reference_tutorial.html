Desain Rolling 2-Period & Master Opsional

Residual terbaru cukup memakai dua periode terakhir; master full PPK/GCP dapat berada di periode mana pun.

✓Perubahan desain v0.6.0
Analisis operasional residual zone memakai rolling 2-period: hanya periode sebelumnya P(t-1) dan periode terbaru P(t) yang dihitung ulang. Histori lama tetap diarsipkan, tetapi tidak perlu dibaca ulang setiap kali ada periode baru.

00B.1 — Pisahkan tiga konsep

KonsepFungsiApakah wajib?
Rolling analysis pairDua periode berurutan yang sedang dianalisis, mis. P4 → P5.Ya, untuk residual zone terbaru.
Master registrationPeriode dengan georeferensi terbaik (full PPK / GCP lengkap) sebagai reference frame XYZ.Opsional; sangat berguna untuk konsistensi spatial jangka panjang.
Common terrain referenceSatu DTM yang dipakai untuk semua periode.Tidak wajib. Untuk tinggi relatif, DTM per periode boleh digunakan selama normalisasi masing-masing valid.
◆Koreksi konsep penting
Untuk tinggi relatif, offset vertikal absolut yang seragam pada satu periode akan banyak tereliminasi saat menghitung Zpoint − Zground dari periode yang sama. Karena itu common DTM bukan syarat mutlak. Yang lebih kritis adalah kualitas DTM lokal, kecocokan XY terhadap TREE_ID, dan konsistensi rekonstruksi tajuk.

00B.2 — Konfigurasi jumlah periode fleksibel

Jumlah histori boleh P1, P2, P3, …, Pn. Untuk proses terbaru, cukup tunjuk dua periode berurutan. Periode dengan full PPK dapat berada di P2, P3, P4, atau periode mana pun.

R CONSOLE

# Residual zone terbaru:

00B.3 — Aturan rolling

Histori:     P1 ── P2 ── P3 ── P4 ── P5 ── P6 ...

Analisis P5:                    [ P4 + P5 ]
Analisis P6:                              [ P5 + P6 ]

Master global opsional: P3 (full PPK)
P4 dan P5 cukup sudah berada / dicek terhadap frame P3.
Tidak perlu memproses ulang P1 dan P2 untuk residual P5.
▲Jangan chain registration tanpa kontrol
Jika master global P3 sudah ditetapkan, periode baru sebaiknya disejajarkan/di-QC terhadap reference frame P3 atau kontrol stabil yang sama. Hindari akumulasi transformasi P3→P4→P5→P6 bila error tiap tahap tidak diketahui.

qc_las <- function(las) {
  las <- filter_duplicates(las)

  las <- tryCatch({
    tmp <- classify_noise(las, sor(k = 10, m = 3))
    filter_poi(tmp, Classification != 18L)
  }, error = function(e) las)

  dens <- rasterize_density(las, res = 1)

  list(
    las = las,
    density = dens,
    avg_density = as.numeric(
      terra::global(dens, "mean", na.rm = TRUE)[1,1]
    )
  )
}

03

Spatial Registration QC — Opsional tetapi Terkontrol

Full PPK/GCP terbaik dapat menjadi reference; transformasi hanya bila memang diperlukan.

✓Prinsip untuk tinggi relatif
Jika kedua periode sudah mempunyai planimetri yang baik terhadap TREE_ID, jangan memaksakan ICP/transformasi tambahan. Untuk analisis relatif, registrasi berlebihan dapat memasukkan bias baru. Lakukan transformasi hanya jika QC menunjukkan offset atau deformasi yang nyata.

03.1 — Pilih reference untuk QC spatial

Jika periode terbaru adalah full PPK/GCP terbaik, periode itu boleh menjadi reference lokal. Jika sudah ada master global (mis. P3 full PPK), gunakan master tersebut sebagai audit frame; periode lama tidak harus dihitung ulang.

Kasus A — P(t) paling baik:
P(t-1)  → QC / align → P(t)

Kasus B — sudah ada master global P3:
P(t-1)_registered ┐
                  ├── keduanya sudah berada di frame P3
P(t)_new → P3 ────┘

03.2 — Gunakan stable features

Evaluasi alignment memakai jalan, bare ground stabil, bangunan permanen, struktur beton, atau area lain yang tidak berubah. Jangan memakai tajuk sawit untuk fitting transform karena tajuk memang berubah antarsemester.

Temuan QCTindakan
XY cocok, tidak ada tilt nyataTidak perlu transformasi tambahan.
Hanya offset Z absolut seragamUntuk tinggi relatif, offset ini biasanya hilang setelah normalisasi periode masing-masing; catat untuk QC absolut.
XY bergeserPerbaiki planimetric registration sebelum buffer TREE_ID.
Ada rotasi/tilt/deformasi blokGunakan rigid/advanced registration pada stable surfaces; validasi ulang setelah transform.
Tidak yakinJangan lanjut ke interpretasi residual sampai geometry stabil.
▲Tentang ICP
R/lidR bukan workflow utama untuk ICP fotogrametri penuh. Bila diperlukan transformasi rigid 3D yang nyata, gunakan workflow registration yang tervalidasi (mis. software fotogrametri/point-cloud dedicated), lalu bawa LAS hasil registered kembali ke R. Tutorial ini tidak memaksakan transformasi yang tidak dapat divalidasi.

05

Validasi Terrain & Noise Floor Minimum

Gunakan hold-out ground untuk menilai kualitas DTM, bukan sekadar visual.

Kesalahan terrain lokal langsung masuk ke tinggi relatif. Karena itu DTM harus diuji. Jangan hanya melihat mean ground setelah normalisasi karena titik yang sama dapat ikut membentuk DTM. Lebih baik gunakan hold-out ground validation bila jumlah ground point mencukupi.

05.1 — Fungsi validasi terrain dengan hold-out ground

R CONSOLE
terrain_holdout_qc <- function(las_grounded,
                               dtm_res = 0.5,
                               train_frac = 0.80,
                               seed = 42) {

  ground <- filter_ground(las_grounded)
  if (npoints(ground) < 100) {
    return(data.frame(
      n_ground = npoints(ground),
      rmse = NA_real_,
      median = NA_real_,
      nmad = NA_real_,
      p95_abs = NA_real_
    ))
  }

  set.seed(seed)
  idx <- sample(
    seq_len(npoints(ground)),
    size = floor(train_frac * npoints(ground))
  )

  # Ambil XYZ sebagai data frame
  gdf <- data.frame(
    X = ground$X,
    Y = ground$Y,
    Z = ground$Z
  )

  train_xyz <- gdf[idx, ]
  test_xyz  <- gdf[-idx, ]

  train_las <- LAS(train_xyz)
  st_crs(train_las) <- st_crs(las_grounded)

  dtm_train <- rasterize_terrain(
    train_las, res = dtm_res, algorithm = tin()
  )

  test_vect <- vect(
    test_xyz,
    geom = c("X","Y"),
    crs = crs(dtm_train)
  )

  zhat <- terra::extract(dtm_train, test_vect)[,2]
  r <- test_xyz$Z - zhat
  r <- r[is.finite(r)]

  med <- median(r)
  r0 <- r - med

  data.frame(
    n_ground = nrow(gdf),
    rmse = sqrt(mean(r0^2)),
    median = med,
    nmad = 1.4826 * median(abs(r0)),
    p95_abs = as.numeric(
      quantile(abs(r0), 0.95, names = FALSE)
    )
  )
}

qc_terrain_prev <- terrain_holdout_qc(g_prev)
qc_terrain_curr <- terrain_holdout_qc(g_curr)

qc_terrain_prev
qc_terrain_curr

✓Mengapa offset absolut bisa hilang

Yang tetap berbahaya adalah error terrain lokal, XY mismatch, deformasi non-rigid, atau perubahan rekonstruksi tajuk.

07

Buffer 2 m, P95 & Presence Support

P95 adalah tinggi utama; point count dan vegetation ratio menjadi QC keberadaan struktur tajuk.

Setiap TREE_ID memakai fixed circular buffer 2 m. Karena TBM belum saling bersentuhan tajuknya, pendekatan ini sederhana dan cukup aman selama posisi TREE_ID benar.

07.1 — Ekstraksi metrik point cloud langsung

R CONSOLE
BUFFER_M <- 2.0
MIN_VEG_H_M <- 0.30  # filter teknis; bukan batas agronomi

top_mean <- function(z, prop) {
  z <- sort(z[is.finite(z)], decreasing = TRUE)
  if (!length(z)) return(NA_real_)
  n <- max(1L, ceiling(length(z) * prop))
  mean(z[seq_len(n)])
}

metrics_one_tree <- function(las, x, y,
                             radius = 2.0,
                             min_veg_h = 0.30) {

  clip <- clip_circle(
    las,
    xcenter = x,
    ycenter = y,
    radius = radius
  )

  if (is.null(clip) || npoints(clip) == 0L) {
    return(data.frame(
      n_all = 0L, n_veg = 0L, veg_ratio = NA_real_,
      p95 = NA_real_, p99 = NA_real_,
      top10 = NA_real_, top20 = NA_real_, top30 = NA_real_
    ))
  }

  z_all <- clip$Z[is.finite(clip$Z)]
  z_veg <- z_all[z_all >= min_veg_h]

  if (!length(z_veg)) {
    return(data.frame(
      n_all = length(z_all), n_veg = 0L, veg_ratio = 0,
      p95 = NA_real_, p99 = NA_real_,
      top10 = NA_real_, top20 = NA_real_, top30 = NA_real_
    ))
  }

  data.frame(
    n_all = length(z_all),
    n_veg = length(z_veg),
    veg_ratio = length(z_veg) / length(z_all),
    p95 = quantile(z_veg, 0.95, names = FALSE),
    p99 = quantile(z_veg, 0.99, names = FALSE),
    top10 = top_mean(z_veg, 0.10),
    top20 = top_mean(z_veg, 0.20),
    top30 = top_mean(z_veg, 0.30)
  )
}

  )
}))

07.3 — Presence support, bukan klaim biologis

n_all membantu membedakan data gap dari tidak adanya point vegetasi. n_veg dan veg_ratio menunjukkan dukungan point canopy-like. Ini disebut presence support, bukan otomatis “pohon hidup”.

R CONSOLE
low_fence <- function(x) {
  x <- x[is.finite(x)]
  if (length(x) < 4) return(0)
  max(0, quantile(x, 0.25) - 1.5 * IQR(x))
}

cuts_prev <- list(
  n_all = low_fence(met_prev$n_all),
  n_veg = low_fence(met_prev$n_veg),
  ratio = low_fence(met_prev$veg_ratio)
)

cuts_curr <- list(
  n_all = low_fence(met_curr$n_all),
  n_veg = low_fence(met_curr$n_veg),
  ratio = low_fence(met_curr$veg_ratio)
)

presence_flag <- function(m, cuts) {
  data.frame(
    data_ok = m$n_all >= cuts$n_all,
    canopy_support =
      is.finite(m$p95) &
      m$n_veg >= cuts$n_veg &
      m$veg_ratio >= cuts$ratio
  )
}

prs_prev <- presence_flag(met_prev, cuts_prev)
prs_curr <- presence_flag(met_curr, cuts_curr)
▲Tidak ada fixed canopy threshold biologis
Karena belum ada ground-truth tinggi/struktur tajuk, tutorial tidak menetapkan angka biologis universal untuk menyatakan pohon “ada/tidak ada”. Cutoff point support dibuat data-driven dan hasil akhirnya tetap memerlukan orthophoto/point-cloud re-check pada residual.

Delta Multi-Metrik & Technical Uncertainty

Δ≈0 dengan tajuk tetap hadir bukan otomatis residual; nilai kecil dapat berada dalam noise sistem.

08.1 — Bentuk satu tabel pasangan periode

R CONSOLE
pair <- trees %>%
  st_drop_geometry() %>%
  transmute(tree_id = as.character(.data[[ID_FIELD]])) %>%
  bind_cols(

08.2 — Internal metric disagreement

Jika P95, Top10, Top20, dan Top30 memberi delta yang sangat berbeda pada satu pokok, kemungkinan masalahnya lebih teknis daripada biologis. P99 tetap disimpan sebagai diagnostik tetapi tidak dijadikan penentu utama karena lebih sensitif ke ujung/noise.

R CONSOLE
pair <- pair %>%
  rowwise() %>%
  mutate(
    metric_spread = max(
      c(d_p95, d_t10, d_t20, d_t30),
      na.rm = TRUE
    ) - min(
      c(d_p95, d_t10, d_t20, d_t30),
      na.rm = TRUE
    ),
    n_negative = sum(
      c(d_p95, d_t10, d_t20, d_t30) < 0,
      na.rm = TRUE
    )
  ) %>%
  ungroup()

spread_cut <- quantile(
  pair$metric_spread,
  0.75, na.rm = TRUE
) + 1.5 * IQR(
  pair$metric_spread,
  na.rm = TRUE
)

pair <- pair %>%
  mutate(
    metric_disagree =
      is.finite(metric_spread) &
      metric_spread > spread_cut
  )

08.3 — T_tech: threshold teknis konservatif

Karena tidak tersedia pengukuran tinggi lapangan atau repeated flight yang identik, kita tidak mengklaim mempunyai “measurement error” lengkap. Kita membuat technical uncertainty proxy dari dua komponen: terrain hold-out uncertainty dan internal disagreement antar estimator tajuk.

R CONSOLE
# Terrain component
T_TERRAIN <- sqrt(
  qc_terrain_prev$nmad^2 +
  qc_terrain_curr$nmad^2
)

# Canopy/internal metric component:
T_METRIC <- as.numeric(
  quantile(
    pair$metric_spread,
    0.95,
    na.rm = TRUE
  )
)

# Conservative technical proxy
T_TECH <- max(
  T_TERRAIN,
  T_METRIC,
  na.rm = TRUE
)

cat("T_TERRAIN =", T_TERRAIN, "m\n")
cat("T_METRIC  =", T_METRIC, "m\n")
cat("T_TECH    =", T_TECH, "m\n")
◆Interpretasi T_TECH
T_TECH bukan ambang agronomi dan bukan bukti bahwa perubahan di bawah nilai itu pasti nol. Artinya: perubahan kecil pada kisaran tersebut belum cukup kuat untuk dibedakan dari ketidakpastian teknis yang tersedia pada dataset ini.

08.4 — Kenapa Δ≈0 tidak otomatis residual?

KondisiMakna aman

09

Threshold Residual & Decision Logic

Residual = bukti teknis/struktur yang kuat, bukan sekadar delta kecil.

Karena tidak ada standar agronomi minimum pertumbuhan, residual dari tinggi tidak boleh memakai batas tetap seperti 0,10 m. Gunakan peer-based robust lower outlier dan technical uncertainty secara bersamaan.

09.1 — Tentukan peer group

Jika tersedia field blok/batch tanam yang valid, gunakan itu. Jika tidak tersedia, fallback ke kuartil tinggi P95 periode sebelumnya agar pokok yang sangat berbeda ukurannya tidak langsung dibandingkan sebagai satu populasi.

R CONSOLE
# Fallback: peer berdasarkan kuartil P95 periode sebelumnya
q <- quantile(
  pair$p95_prev,
  probs = c(0.25, 0.50, 0.75),
  na.rm = TRUE
)

breaks <- unique(c(-Inf, q, Inf))

if (length(breaks) >= 3) {
  pair$peer <- cut(
    pair$p95_prev,
    breaks = breaks,
    include.lowest = TRUE,
    labels = FALSE
  )
} else {
  pair$peer <- 1L
}

09.2 — Lower outlier threshold per peer

Threshold residual dibuat konservatif: sebuah delta harus berada di bawah lower fence kelompoknya dan melewati sisi negatif technical uncertainty.

R CONSOLE
peer_limits <- pair %>%
  filter(
    canopy_support_prev,
    canopy_support_curr,
    !metric_disagree,
    is.finite(d_p95)
  ) %>%
  group_by(peer) %>%
  summarise(
    q1 = quantile(d_p95, 0.25, na.rm = TRUE),
    q3 = quantile(d_p95, 0.75, na.rm = TRUE),
    iqr = IQR(d_p95, na.rm = TRUE),
    lower_peer = q1 - 1.5 * iqr,
    upper_peer = q3 + 1.5 * iqr,
    n_peer = n(),
    .groups = "drop"
  ) %>%
  mutate(
    # Harus lebih negatif daripada noise floor teknis
    lower_residual = pmin(
      lower_peer,
      -T_TECH
    )
  )

pair <- pair %>%
  left_join(peer_limits, by = "peer")

09.3 — Decision logic residual

R CONSOLE
pair <- pair %>%
  mutate(
    status = case_when(

      # Data gap: total point support rendah
      !data_ok_curr ~ "TECH_DATA_GAP_CURRENT",

      # Previous ada dukungan tajuk, current kehilangan dukungan
      canopy_support_prev &
        !canopy_support_curr &
        data_ok_curr ~ "CANOPY_LOSS_OR_RECONSTRUCTION",

      # Keduanya tidak punya canopy support namun data cukup
      !canopy_support_prev &
        !canopy_support_curr &
        data_ok_prev &
        data_ok_curr ~ "NO_CANOPY_SUPPORT_BOTH",

      # Metrik tinggi antar-estimator tidak konsisten
      metric_disagree ~ "TECH_METRIC_DISAGREEMENT",

      # Negative outlier harus:
      # 1) canopy support valid di kedua periode
      # 2) dP95 di bawah lower_residual
      # 3) >=3 dari 4 metrik utama sama-sama negatif
      canopy_support_prev &
        canopy_support_curr &
        is.finite(lower_residual) &
        d_p95 < lower_residual &
        n_negative >= 3 ~ "NEGATIVE_HEIGHT_OUTLIER",

      # Tajuk hadir dan perubahan kecil relatif ke noise teknis
      canopy_support_prev &
        canopy_support_curr &
        abs(d_p95) <= T_TECH ~ "STABLE_NO_DETECTABLE_CHANGE",

      # Lainnya: tajuk masih didukung, tidak masuk residual keras
      canopy_support_curr ~ "PRESENT_NO_HARD_RESIDUAL",

      TRUE ~ "REVIEW"
    ),

    residual_flag = status %in% c(
      "TECH_DATA_GAP_CURRENT",
      "CANOPY_LOSS_OR_RECONSTRUCTION",
      "NO_CANOPY_SUPPORT_BOTH",
      "TECH_METRIC_DISAGREEMENT",
      "NEGATIVE_HEIGHT_OUTLIER",
      "REVIEW"
    )
  )
✓Aturan utama
Pokok dengan tinggi relatif hampir sama pada dua periode dan canopy support tetap baik → STABLE_NO_DETECTABLE_CHANGE, bukan residual. Ini mencegah noise SfM atau pertumbuhan kecil langsung dianggap masalah.
